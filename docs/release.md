# Приёмка и выпуск Study Cards

## CI и черновик

На каждом PR и после слияния в `main` GitHub Actions запускает на Linux `npm ci`, `npm run typecheck`, `npm test` и `npm run build`. В правилах ветки `main` обязательна проверка **Study Cards checks** от GitHub Actions. CI и сборка черновика читают версию Node.js из [`.node-version`](../.node-version).

1. Проверьте, что `manifest.json` содержит новую версию `x.y.z`, `id: study-cards` и `isDesktopOnly: false`. Изменения манифеста и файлов плагина проведите через PR.
2. После успешного CI на `main` поставьте тег на проверенный коммит. Подставьте версию из манифеста и хеш проверенного коммита.

   ```sh
   git fetch origin main
   git tag -a x.y.z <commit> -m "Study Cards x.y.z"
   git push origin refs/tags/x.y.z
   ```

3. В [Actions](https://github.com/verf1x/obsidian-study-cards/actions) откройте **Draft release** для тега. Workflow проверяет версию и принадлежность коммита `main`, повторяет проверки CI и создаёт черновик с тремя вложениями. Если загрузка оборвалась и остался неполный черновик, удалите этот черновик перед повторным запуском. Существующие вложения workflow не заменяет.
4. Скачайте из черновика `main.js`, `manifest.json` и `styles.css` в один каталог. Запишите тег, коммит и SHA-256 каждого файла. Этот комплект используется на всех платформах. Готовый `main.js` содержит уведомления о лицензиях включённых зависимостей.

## Чистый тестовый vault

Укажите новый каталог под vault и папку со скачанными вложениями. Тестовые заметки берите из checkout того же тега.

```sh
npm run test-vault -- "../Study Cards acceptance" "../Study Cards assets"
```

Для проверки локальной сборки выполните `npm ci` и `npm run build`, затем вызовите `npm run test-vault` с одним аргументом, путём к новому vault. Для нового прогона используйте новый каталог. На Android перенесите весь подготовленный vault, включая скрытую папку `.obsidian`, в доступную Obsidian папку устройства. Откройте папку как vault и включите Study Cards в настройках сторонних плагинов.

## Первый сквозной сценарий и сравнение с Decks

Начинайте после того, как в рабочую сборку войдут свободная проверка и повтор ошибок. [#18](https://github.com/verf1x/obsidian-study-cards/issues/18)

1. Создайте учебный раздел. Подключите `Материалы/HTTP — 100 вопросов.md` как коллекцию по заголовкам H2. Проверьте 100 карточек в каталоге.
2. Запустите свободную проверку на 20 вопросов в стандартном порядке. Раскройте первый ответ про ETag. Проверьте подзаголовки, списки, таблицу, HTTP-код, выноску и ссылки.
3. Поставьте «Ошибка» на вопросах 1, 7 и 13, остальным поставьте «Верно». Подтвердите итог. Запустите повтор ошибок и сравните его состав и порядок с этими тремя вопросами. Завершите повтор и проверьте отдельные результаты в истории.
4. В чистой копии vault используйте тот же конспект в Decks. Добавьте тег профиля Decks в свойства заметки. Включите экзамен для профиля с карточками по H2. Выберите 20 вопросов по порядку файла, без перемешивания, с немедленной обратной связью и самооценкой. Повторите оценки там, где их позволяет интерфейс. После завершения попробуйте запустить отдельную попытку ровно по вопросам 1, 7 и 13. [Формат карточек](https://decksmd.app/docs/cards/header-paragraph/) · [Экзамен Decks](https://decksmd.app/docs/exams/taking-an-exam/)
5. Запишите версию Decks, что отобразилось в длинном ответе, шаги запуска повтора, его фактический набор вопросов и какие результаты остались в истории обоих плагинов. Отдельно укажите действия, которые не удалось выполнить. [Решение о сравнении #12](https://github.com/verf1x/obsidian-study-cards/issues/12#issuecomment-7047678406)

## Приёмка полного MVP

Начинайте после завершения [#18](https://github.com/verf1x/obsidian-study-cards/issues/18), [#19](https://github.com/verf1x/obsidian-study-cards/issues/19) и [#23](https://github.com/verf1x/obsidian-study-cards/issues/23). На Windows, Linux и реальном Android-устройстве установите файлы из одного черновика и повторите сценарий Study Cards. На Android выполняйте действия касаниями.

- Во время свободной проверки запишите текущий вопрос и уже выставленные оценки. Полностью закройте Obsidian, откройте его и продолжите сессию. Сверьте состав, порядок, позицию и оценки. Подтвердите итог и проверьте повтор ошибок.
- Допустите карточку до интервального повторения, поставьте оценку и зафиксируйте новый срок. После перезапуска сверьте оценку в истории и срок повторения выбранной карточки.
- На Windows и Android используйте две копии тестового vault с одинаковыми Markdown-заметками и UUID. Начните проверку на Windows, вручную перенесите `Study Cards/data.json` на Android и продолжите сессию. Измените оценку, перейдите к следующему вопросу и перенесите файл обратно на Windows. Проверьте обновление открытой вкладки.
- Сохраните разные оценки на Windows и Android, начав с одинакового состояния. Доставьте одну версию файла на второе устройство. Сверьте доступные версии и проверьте, что запись заблокирована до выбора. Перенесите выбранное состояние обратно и убедитесь, что проверку можно продолжить в обеих копиях. [Спецификация #23](https://github.com/verf1x/obsidian-study-cards/issues/23)
- Экспортируйте снимок прогресса в JSON. Отдельно скопируйте подключённые Markdown-заметки с присвоенными UUID в чистый тестовый vault. Импортируйте JSON и проверьте предпросмотр и восстановленный прогресс. В отдельной тестовой копии повредите `Study Cards/data.json` после сохранения прогресса, откройте плагин и проверьте восстановление локальной копии через интерфейс.

Для каждого прогона сохраните дату, тег, коммит, контрольные суммы трёх вложений и заполните строки проверки.

## Минимальная версия Obsidian

Проверяйте совместимость с версией из `minAppVersion`. Сверяйте используемые `MarkdownRenderer.render`, `Vault.process`, `DataAdapter.process`, методы локального хранилища `App` и `Vault.create` для мобильного экспорта. Перед финальным кандидатом заново сверьте используемые API Obsidian и Web API. Текущая рабочая сборка использует `crypto.randomUUID`, `crypto.subtle.digest` и `TextEncoder`. Для FSRS дополнительно сверьте требования JavaScript и WebView. [Исследование ts-fsrs](research/ts-fsrs.md)

Укажите в `minAppVersion` самую старую версию, на которой полный прогон прошёл на всех трёх платформах. Если старые клиенты недоступны для проверки на всех трёх, используйте проверенную стабильную версию. Запишите подтверждённый минимум и проверенные платформы в README. macOS и iOS остаются доступными для установки со статусом «совместимость не проверена». При изменении минимума после публикации обновите [`versions.json`](https://docs.obsidian.md/Reference/Versions), сохранив совместимые выпуски.

## Публикация

Если по итогам приёмки изменилась сборка, включая манифест, проведите правку через PR, поднимите версию и повторите приёмку из нового черновика. Правки описания релиза можно внести в уже проверенный черновик.

После успешной приёмки на всех трёх платформах вручную опубликуйте тот же черновик. Скачайте три файла из публичного релиза и сверьте SHA-256 с протоколом. Для первого публичного выпуска подайте Study Cards через Community Directory. После проверки каталога подтвердите установку из Community plugins. [Подача плагина](https://docs.obsidian.md/plugins/releasing/submit-plugin)
