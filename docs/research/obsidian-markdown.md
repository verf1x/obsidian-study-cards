# Obsidian API для Markdown-источников

Исследование по задаче [Возможности Obsidian API для Markdown-источников](https://github.com/verf1x/obsidian-study-cards/issues/5). Правила выбора секций и тегов остаются предметом задачи [Подключение заметок и правила метаданных карточек](https://github.com/verf1x/obsidian-study-cards/issues/7).

## Метаданные и позиции

- `MetadataCache.getFileCache(file)` возвращает кэш заметки или `null`, пока кэш недоступен. Поля `CachedMetadata` необязательны. `headings` даёт заголовки с уровнем и позицией, `sections` — блоки Markdown верхнего уровня, `listItems` — элементы списка, `blocks` — записи по явным ID блоков. Для YAML доступны разобранный `frontmatter` и его диапазон `frontmatterPosition`. В коллекции Study Cards может взять заголовок выбранного уровня как начало карточки и вычислить её конец по следующему заголовку согласно правилам плагина. [CachedMetadata](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L2391-L2553), [HeadingCache](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L5110-L5122)
- `getAllTags(cache)` собирает теги заметки из свойства `tags` во frontmatter и из Markdown-текста. Он возвращает строки без позиций или `null`. Для тегов секции используйте позиции `TagCache` в пределах её текста, а теги frontmatter читайте как метаданные всей заметки. Нужно проверить, какие вхождения реально попадают в `cache.tags`, и отдельно согласовать наследование тегов заметки карточками. [getAllTags](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L5017-L5041), [TagCache](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L9766-L9773), [теги Obsidian](https://obsidian.md/help/tags)
- `Pos` содержит `start` и `end`. В каждой границе есть `line` и `col` с отсчётом от нуля и `offset` от начала файла. Для извлечения берите `data` и `cache` из одного события `MetadataCache.on('changed', …)` после индексации. Перед применением позиций к файлу или редактору сравните полный текущий текст с этим `data`. При расхождении дождитесь совпадающего снимка кэша или заново вычислите диапазон по текущему тексту. Переименование обрабатывайте через `Vault.on('rename', …)`, поскольку событие `changed` при нём не вызывается. [Loc](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L5749-L5766), [Pos](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L7561-L7573), [MetadataCache](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L6467-L6522)

## Запись изменений

- `Vault.process(file, fn)` атомарно читает, синхронно преобразует и сохраняет содержимое файла. `Vault.modify(file, data)` записывает переданную строку целиком. Для закрытой заметки вычисляйте замену по строке в callback `process`. Если диапазон подготовлен заранее, сравните исходный снимок с этой строкой внутри callback и прервите запись при расхождении. [Vault](https://docs.obsidian.md/Plugins/Vault#Modify+files)
- Несохранённый текст открытого редактора живёт в памяти. По пояснению разработчика Obsidian, `Vault.process` и `Vault.modify` работают с файлом на диске, а редактор при отложенном сохранении может объединить дисковое изменение со своим буфером. Для правки открытой заметки в режиме редактирования проверьте, что `MarkdownView` относится к нужному файлу, возьмите текущую строку через `view.editor.getValue()` и примените правку к ней через `Editor.replaceRange()` или `Editor.transaction()`. Преобразуйте смещения через `offsetToPos()` после сверки со строкой редактора. [Editor](https://docs.obsidian.md/Plugins/Editor/Editor), [преобразование позиций](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L3872-L3886), [пояснение разработчика](https://forum.obsidian.md/t/vault-process-and-vault-modify-dont-work-when-there-is-a-requestsave-debounce-event/107862/3)
- `FileManager.processFrontMatter(file, fn)` атомарно обновляет свойства переданного Markdown-файла через синхронную мутацию JS-объекта. Невалидный YAML вызывает `YAMLParseError`, ошибка callback передаётся вызывающему коду. При обратной сериализации комментарии могут исчезнуть, а кавычки и форматирование измениться даже у соседних полей. Если нужно сохранить исходное оформление, понадобится точечная правка исходного текста с проверкой снимка. Поведение `processFrontMatter` при несохранённом буфере требует отдельной проверки. [processFrontMatter](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L4436-L4456), [пояснение разработчика](https://forum.obsidian.md/t/yaml-properties-api-processfrontmatter-removes-alters-string-quotes-comments-types-formatting/65851/6)

## Показ ответа

`MarkdownRenderer.render(app, markdown, el, sourcePath, component)` принимает готовую строку Markdown, выводит её в `HTMLElement` и использует родительский `Component` для управления жизненным циклом дочерних компонентов. В `sourcePath` передавайте нормализованный путь исходной заметки внутри vault, например `Материалы/Тема.md`. Этот путь задаёт контекст относительных внутренних ссылок. Границы фрагмента определяет вызывающий код. Разрешение вложений из фрагмента и доступность определений ссылок или сносок за пределами фрагмента нужно проверять в приложении. [MarkdownRenderer.render](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L6075-L6085), [внутренние ссылки](https://obsidian.md/help/links), [вложения](https://obsidian.md/help/embeds)

## Проверки в тестовом vault

Прогнать сценарии на desktop и mobile, указать версию Obsidian и ОС. Это план проверок, запуск в приложении не выполнялся.

1. Создать коллекцию с соседними и вложенными заголовками, повторяющимся заголовком, блоками кода с `#` и списками. Добавить теги в тело и в YAML, включая повтор, вложенный тег и похожий текст в коде. Записать, что попадает в кэш, и сверить реальные срезы по `start` и `end` для LF, CRLF и эмодзи перед границами. [CachedMetadata](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L2391-L2553)
2. Сразу после ручной вставки строки перед карточкой сравнить `editor.getValue()`, `vault.read()` и пару `data/cache` из `changed`. Проверить Live Preview и Source mode, открытую и закрытую заметки, два представления одного файла там, где доступны, и переименование. Убедиться, что устаревшая позиция не приводит к записи в соседнюю карточку и ручные правки сохраняются после автосохранения. [Editor](https://docs.obsidian.md/Plugins/Editor/Editor), [пояснение разработчика](https://forum.obsidian.md/t/vault-process-and-vault-modify-dont-work-when-there-is-a-requestsave-debounce-event/107862/3)
3. Изменить одно свойство через `processFrontMatter` в файле с комментариями, кавычками, списком и многострочным значением. Сравнить весь YAML и тело до и после, повторить с невалидным YAML и при несохранённой правке в редакторе. [processFrontMatter](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L4436-L4456), [пояснение разработчика](https://forum.obsidian.md/t/yaml-properties-api-processfrontmatter-removes-alters-string-quotes-comments-types-formatting/65851/6)
4. Показать один ответ с `![[assets/schema.png]]`, `![схема](./assets/schema.png)`, вложенной заметкой по заголовку или ID блока и ссылкой с определением за границей ответа. Положить одноимённые изображения в разных папках, сверить фактическое вложение с режимом чтения и повторить после переноса исходной заметки. [MarkdownRenderer.render](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L6075-L6085), [вложения](https://obsidian.md/help/embeds)
5. Добавить в ответ изображение по внешнему HTTPS-адресу с пустым кэшем. Проверить сетевой запрос до и после раскрытия ответа, а также показ без сети. По результату согласовать политику загрузки внешних изображений для офлайн-режима. [Внешние изображения в Obsidian](https://obsidian.md/help/embeds#Embed+an+image+in+a+note)
6. Проверить в ответе блок кода с подсветкой, формулу LaTeX, диаграмму Mermaid и сворачиваемый callout с локальным изображением. Сравнить с режимом чтения, в том числе без сети. [Блоки кода](https://obsidian.md/help/syntax#Code+blocks), [Mermaid и LaTeX](https://obsidian.md/help/advanced-syntax), [callouts](https://obsidian.md/help/callouts)
7. Быстро переключить карточки и закрыть экран, пока строится диаграмма или загружается вложение. Проверить, что отображается только актуальный ответ, а дочерние компоненты предыдущего ответа выгружаются при переключении и закрытии. [MarkdownRenderer.render](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L6075-L6085), [Component](https://github.com/obsidianmd/obsidian-api/blob/737629a51f6b4d30f8336fa3d38f3df006e322d4/obsidian.d.ts#L2983-L3024)
