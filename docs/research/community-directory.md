# Community Directory и плагины для учёбы

Проверено 20 ноября 2026 года. Сценарий Study Cards — подключить Markdown-конспект из 100 готовых вопросов, провести локальную свободную проверку 20 вопросов и пройти отдельную попытку по ошибкам. [Аудит похожих плагинов и требований Community Directory](https://github.com/verf1x/obsidian-study-cards/issues/4) · [Сценарий первого релиза](https://github.com/verf1x/obsidian-study-cards/issues/3)

## Публикация

- **Подача.** Подготовить публичный GitHub-репозиторий с `README.md`, `LICENSE` и `manifest.json` в корне ветки по умолчанию. Опубликовать первый GitHub Release, войти в Community Directory через аккаунт Obsidian, привязать GitHub и отправить URL репозитория через **Add a plugin**. Каталог читает manifest из HEAD ветки по умолчанию и проверяет manifest, релиз, исходники и соответствие сборки. Ошибки блокируют установку из каталога. После первой подачи достаточно публиковать новые релизы. README шаблона ещё упоминает прежнюю подачу через PR в `obsidian-releases`. [Submit your plugin](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin) · [Manage your plugin or theme](https://docs.obsidian.md/community-directory/manage-entry) · [README шаблона](https://github.com/obsidianmd/obsidian-sample-plugin#adding-your-plugin-to-the-community-plugin-list)
- **Релиз.** Использовать версию `x.y.z` и совпадающий тег без `v`. Прикрепить отдельными файлами `main.js`, `manifest.json` и при наличии `styles.css`. `versions.json` в корне связывает версии плагина с минимальными версиями Obsidian для установки на старых клиентах. Обновлять эту карту при смене `minAppVersion`. Сканер запускает первую доступную production-команду из `build`, `build:plugin`, `compile` в этом порядке. [Submit your plugin](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin) · [Versions](https://docs.obsidian.md/Reference/Versions) · [FAQ](https://docs.obsidian.md/community-directory/faq#which-build-script-is-used-when-scanning)
- **Manifest, имя и ID.** Обязательны `id`, `name`, `version`, `minAppVersion`, `description`, `author` и логическое `isDesktopOnly`. Имя должно быть коротким, уникальным и в базовой латинице, с допустимыми знаками «-», «+» и скобками. Исключить названия встроенных функций и плагинов, слова `Plugin`, `Obsidian` и вариации бренда. Для уникального ID допустимы строчные латинские буквы и дефисы, исключены `obsidian` внутри и `plugin` в конце. ID определяет имя установочной папки, его фиксируют до публикации. Описание — до 250 символов с точкой на конце. В выгрузке каталога на дату проверки точных совпадений с именем `Study Cards` и ID `study-cards` или `qcards` не найдено. Доступность выбранной пары нужно повторно проверить при фиксации имени. [Manifest](https://docs.obsidian.md/Reference/Manifest) · [Submission requirements](https://docs.obsidian.md/community-directory/submission-requirements-for-plugins) · [FAQ](https://docs.obsidian.md/community-directory/faq) · [Выгрузка плагинов](https://github.com/obsidianmd/obsidian-releases/blob/master/community-plugins.json)
- **Лицензии и правила каталога.** Указать лицензию плагина, приложить `LICENSE`, соблюдать лицензии заимствованного кода и зависимостей и сохранить требуемые уведомления. Obsidian проверяет тип лицензии по данным GitHub. Правила каталога допускают форки с публично подтверждённым письменным разрешением автора либо по процедуре для заброшенного проекта. Если появятся сеть, платный доступ, аккаунт или доступ за пределами vault, условия нужно описать в README. Клиентская телеметрия запрещена. [Developer policies](https://docs.obsidian.md/community-directory/developer-policies) · [FAQ о лицензиях](https://docs.obsidian.md/community-directory/faq#why-do-i-get-a-the-repository-does-not-have-a-recognized-license-warning-despite-having-a-valid-license)
- **Кроссплатформенная сборка.** Для единого `main.js` с `isDesktopOnly: false` использовать API Obsidian и Web API в коде плагина и проверить транзитивные зависимости на обращения к Node.js и Electron. Node.js в среде сборки допустим. Плагин, которому нужны Node.js или Electron во время работы, объявляет `isDesktopOnly: true`. Минимальную версию выбрать по реально использованным API и проверке одного релизного комплекта на Windows, macOS, Linux, Android и iOS. Настольная эмуляция помогает проверить интерфейс, фактическую загрузку и сохранение на мобильном проверяют на устройствах. [Mobile development](https://docs.obsidian.md/Plugins/Getting%20started/Mobile%20development) · [Submission requirements](https://docs.obsidian.md/community-directory/submission-requirements-for-plugins) · [Структура репозитория и критерии кроссплатформенного релиза](https://github.com/verf1x/obsidian-study-cards/issues/13)

Перед подачей заполнить метаданные проекта и удалить демонстрационный код. ## Покрытие сценария

Проверка по документации авторов и, для ближайших аналогов, по коду релизов. «Повтор ошибок» здесь означает новую попытку ответить на вопросы, ошибочно оценённые в конкретной сессии.

- **Decks 2.12.9** читает Markdown по заголовкам выбранного уровня и поддерживает вариант «имя файла → весь текст». В локальном экзамене можно выбрать 20 готовых вопросов, ответить в многострочном поле, сравнить ответ с Markdown-эталоном, поставить себе оценку и увидеть историю. Экзамены хранятся отдельно от FSRS. `Retake` делает новую выборку. Сессия по слабым местам из PDF передаёт генератору номера страниц, связанных с ошибками. Это покрывает локальный экзамен и разбор, а отдельная новая попытка по тому же набору ошибок в проверенных путях не подтверждена. [Форматы карточек](https://decksmd.app/docs/cards/overview/) · [Экзамены и FSRS](https://decksmd.app/docs/exams/overview/) · [Настройки и результаты](https://decksmd.app/docs/exams/taking-an-exam/) · [Код ввода и самооценки 2.12.9](https://github.com/dscherdi/decks/blob/2.12.9/src/components/exam/FlashcardExamModal.svelte#L692-L731) · [Код результатов 2.12.9](https://github.com/dscherdi/decks/blob/2.12.9/src/components/exam/FlashcardExamModal.svelte#L912-L999)
- **Plain Deck 1.0.7** читает пары «заголовок H2 → текст» в `*.cards.md` или заметке, открытой как карточки. По умолчанию показывает до 20 **новых карточек на колоду за сессию**. `Again` и шаги переучивания работают по FSRS-6, прогресс хранится скрытой строкой в заметке. Отдельный тест из 20 и новая попытка по ошибкам этого теста в документации не описаны. [Plain Deck](https://community.obsidian.md/plugins/plain-deck)
- **Lemma 1.2.1** читает размеченные Q&A и cloze-карточки в Markdown. Можно ограничить размер сессии, отфильтровать карточки по тегу или состоянию FSRS и вводить ответ с автоматической оценкой совпадения. Доступен отбор 20 существующих карточек. Отдельные экзаменационные результаты и новая попытка по их ошибкам в документации не описаны. [Lemma](https://community.obsidian.md/plugins/lemma-flashcards) · [Настройка лимита сессии в 1.2.1](https://github.com/fundaments-work/Lemma/blob/1.2.1/src/ui/CustomStudyModal.ts#L35-L36)
- **LearnKit 1.8.6** генерирует тест из заметки, папки или материала колоды через настроенного ИИ-провайдера. В интерфейсе доступна цель **20 вопросов**. Сохраняет попытки и показывает ответы, объяснения и ошибки. В коде этой версии `Review mistakes` открывает результаты ниже полного балла, без нового ввода ответа. [Tests](https://ctrlaltwill.github.io/LearnKit/Tests/) · [Выбор числа вопросов](https://github.com/ctrlaltwill/LearnKit/blob/1.8.6/src/views/exam-generator/exam-generator-view.ts#L1630) · [Обработчик Review mistakes](https://github.com/ctrlaltwill/LearnKit/blob/1.8.6/src/views/exam-generator/exam-generator-view.ts#L2902-L2911)
- **Spaced Repetition 1.15.4** читает Q&A и cloze-разметку, планирует повторение карточек и целых заметок по FSRS или SM-2. `Cram` позволяет пройти все карточки доступной колоды или заметки вне расписания. `Again` позволяет повторить карточку в тот же день. Отбор 20 вопросов как отдельного теста с новой попыткой по его ошибкам в документации не описан. [Spaced Repetition](https://community.obsidian.md/plugins/obsidian-spaced-repetition) · [Журнал изменений](https://github.com/st3v3nmw/obsidian-spaced-repetition/blob/main/docs/docs/changelog.md)

## Возможное отличие Study Cards

Наиболее близкий аналог — Decks. Гипотеза отличия — отдельная попытка по ошибкам конкретной свободной проверки. Целевой путь включает 20 исходных вопросов, воспроизведение длинного технического ответа, сверку с полным Markdown-эталоном, самооценку и повторный ответ на вопросы из списка ошибок. Её результаты входят в историю свободных проверок, продуктовый сценарий работает локально. Источники подтверждают сходство отдельных функций. Для проверки отличия и удобства нужен один и тот же конспект из 100 вопросов в Decks и Study Cards с сопоставлением шагов до повторной попытки, отображения длинного ответа и сохранения результата. Этот аудит ограничен пятью указанными плагинами и выполнен без их запуска.
