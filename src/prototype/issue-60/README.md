# Study Cards · прототип #60

**Утверждён вариант A.** При выборе заметки настройки карточек раскрываются под её названием. В списке одновременно открыты настройки одной заметки. Чтобы вернуться к выбранной заметке, нажмите её счётчик или «Настроить». Под названием заметки показаны «Вся заметка» и подходящие уровни заголовков с количеством карточек. После выбора доступен предпросмотр. Так можно настроить одну заметку и продолжить выбор в том же списке.

Макет использует учебные данные и сбрасывает изменения при перезагрузке. Стрелками внизу можно сравнить три варианта.

```powershell
node src/prototype/issue-60/serve.mjs
```

## Что попробовать

1. На пустом экране посмотреть оба примера. Подключить «Кэш браузера» целиком и «HTTP — главы и вопросы» по `###`. Вторая заметка даёт четыре карточки по `##` и двадцать по `###`. Варианты без подходящих заголовков скрыты. Один заголовок первого уровня входит в вариант «Вся заметка». Итог двух заметок — 21 карточка.
2. Открыть и свернуть предпросмотр, проверить итог. Открыть настроенную коллекцию «HTTP — 100 вопросов», проверить первый длинный ответ, внутреннюю ссылку и переключение на последний вопрос. В макете отображается ответ выбранной карточки.
3. Нажать «С разделом» в полосе прототипа. Переименовать HTTP в «Веб», найти старый результат по новому названию. Выбрать один из двух разделов SQL в «Истории» и вернуться в «Практику». Удалить «Веб» и найти «Веб · раздел удалён» в общей истории.
4. Переключить тему или язык в полосе прототипа. Язык учебного Markdown сохраняется.

## Согласованные правила

- Пользователь выбирает, как сделать карточки из новой заметки. На кнопке уровня указано количество карточек. Счётчик строки и общий итог используют одни и те же настройки. Для заметки с сохранёнными настройками сразу показываются способ создания и количество карточек.
- При создании карточек по заголовкам ответ заканчивается перед следующим заголовком того же или более высокого уровня. При одной карточке источником вопроса может быть первый `#` или имя файла. Если первого `#` нет, используется имя файла.
- Два примера есть на пустом главном экране. После подключения они раскрываются по ссылке «Как из заметок получаются карточки» в форме. Поиск, папка и нижние действия остаются доступны при прокрутке списка и длинного ответа.
- В истории один фильтр по ID раздела. Он сохраняется при переходе между вкладками и не меняет активный раздел практики. Новый фильтр начинается с «Все разделы». После удаления выбранного раздела фильтр возвращается к «Все разделы». Старые результаты отображают последнее название раздела.
- Переименование сохраняет ID, источники, прогресс, незавершённую проверку и старые результаты. Подключение продолжает проверять актуальность Markdown и записывает свойства и UUID после подтверждения. ## Замеры предпросмотра

Windows, Obsidian 1.15.1, опубликованная Study Cards 0.1.6, отдельный vault. Проверены короткая заметка «Энтропия источника», настроенная коллекция из 100 вопросов и копия этой коллекции без метаданных со 101 внутренней ссылкой. Сняты CPU-профили при раскрытии и при программном движении указателя с прокруткой. Сильный фриз не воспроизвёлся на этих данных. Коллекция при раскрытии создала 100 ответов. Длинная копия в режиме одной карточки создала один ответ и 101 ссылку. Даже при раскрытом предпросмотре высота списка составила 440 px при высоте панели около 722 px.

Перед исправлением фриза нужен сценарий, на котором проявляется симптом. Снять запись Performance с событиями указателя, стилями, компоновкой и отрисовкой на заметке и теме с проявлением фриза. Сравнить со стандартным оформлением и, отдельно, с настройкой «Предпросмотр страницы». Раздельно проверить открытие, движение после открытия, прокрутку и повторное раскрытие. Вариант с одним ответом в DOM проверять отдельно на коллекции и на длинной заметке-карточке. Граница разбиения и предпросмотр должны брать данные из того же плана, что и подтверждение подключения.
