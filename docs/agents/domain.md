# Domain docs

This repository uses one domain context.

- Read the root `GLOSSARY.md` and relevant decisions in `docs/adr/` when they exist.
- Use glossary terms in issues, proposals, and tests. Raise vocabulary gaps with `domain-modeling`.
- Cite the ADR and explain the conflict when a proposal revisits an existing decision.
- Add glossary entries and ADRs when domain terms or decisions are agreed.
